舞台
固定 1440×720（2:1），所有電腦版畫面、Popover、抽屜、提示都排在舞台內，跟著一起縮放。舞台外以 --color-surface 填滿，不放內容。
縮放（方式 A：transform）
s = Math.min(innerWidth / 1440, innerHeight / 720)
stage: position:fixed; left:50%; top:50%;
       transform: translate(-50%,-50%) scale(s)
resize → 重新計算

toStage(e) {               // 所有拖曳元件共用
  r = stage.getBoundingClientRect()
  return { x:(e.clientX - r.left) / s,
           y:(e.clientY - r.top)  / s }
}
注意：Popover API
原生 popover 會進入 top layer，不受舞台 transform 影響。開啟時需在 popover 本身套用相同倍率（transform-origin 設在錨點側），位置以錨點的 getBoundingClientRect 換算。

切換手機版
可視區寬 < 1024px，或直立（高 > 寬）：不用舞台，改為捲動排版（§7）。
小倍率字級補償（已決議）
倍率 s < 0.89（例如 1280×720，s ≈ 0.83）時，在舞台加上 data-compact：輔助字 13→14、內文 16→17、事件標題 26→24（舞台 px）。實際顯示約為輔助 11.7px、內文 14.1px，和 1366×768 一致。 
stage.toggleAttribute('data-compact', s < 0.89)
:root            { --fs-aux:13px; --fs-body:16px; }
[data-compact]   { --fs-aux:14px; --fs-body:17px; }
補償後文字會多佔約 6% 寬度：敘述面板、Popover、卡片簡介允許多一行；事件列標題超出時截斷（§6-D），版面尺寸不變。

第四主軸含有結局

這一頁會揭露詛咒的真相與最終的選擇。建議讀完前三條主軸後再打開。

我準備好了，打開
A Popover。寬 300、出現在錨點下方 12px，空間不足時翻到上方；錨點文字在開啟時變成選中樣式。內容依進度累積（§6-F）。點外部或 Esc 關閉。群體節點沒有 Popover。
B 托盤。高 168，從底部升起，蓋住頁面下緣但不蓋側欄；側欄「伏筆」為開啟狀態。回收處文字以雙底線標出，框格放在敘述右側的旁註欄（x 466 起），以手繪感的弧線從雙底線末端連出：起點小圓點，線走在行距間避開文字，最後彎向框格左緣。框格不放進段落，避免被看成原文的一部分；空框格的連線為虛線。拖曳時原位置留虛線空位。此例一個事件有三個回收處：已解開、可以放置、空。
