# Contract：內容行內標記與撰寫規則

> 對應需求 #5（文字集中管理）與 #6（讓程式快速找到可放框格的地方）。
> 作者只需要在文字裡加**標記**；位置、樣式、互動全部由程式處理。

---

## 1. 語法

標記格式：`{類型:參數|顯示文字}`，可巢狀（最多 2 層），不跨段落。

| 標記 | 範例 | 渲染結果 |
|---|---|---|
| `{p:id}` | `{p:fane}` | 人名連結，顯示 `people.yaml` 該人的 `name`；點擊開 Popover |
| `{p:id\|顯示文字}` | `{p:elian\|安}` | 人名連結但顯示指定文字（化名、稱號、歧義別名） |
| `{t:id}` / `{t:id\|文字}` | `{t:morning-star}` | 名詞連結（`glossary.yaml`）；點擊開名詞 Popover |
| `{x:target\|文字}` | `{x:spectrum\|見下方 ↓}` | 交叉連結（目前只有 `spectrum`＝01 邊界之辯光譜）；點擊閃動／捲動 |
| `{h:hint-id\|片語}` | `{h:forgotten-gift\|法恩用馬蹄鐵敲出火}` | **伏筆回收處**：雙底線片語；程式量測其位置放置框格與弧線 |

- 純文字中的 `{`、`}` 以 `\{` `\}` 逸出（極少用到）。
- 換行：YAML 以 `>-`（折行）或 `|-`（保留換行）；段落間空一行。

## 2. 人名自動辨識（不必逐一標記）

`RichText` 會依 `people.yaml` 的 `aliases` 自動把文字中的人名包成人名連結：
- **最長優先**（「魔女艾莉絲」先於「艾莉絲」）、同一人物在**同一段落內每次出現都可點**。
- **不自動連結**（`autoLink:false`）：`特使`（也指貴族子弟）、`男人`、`安`（單字）；這些要連結時手動寫 `{p:fane|特使}`、`{p:shadow-man|男人}`、`{p:elian|安}`。
- **名詞優先**：`東方晨星` 同時是德雷文稱號與名詞，一律當名詞（`glossary.yaml`）。
- **群體不連結**：`守舊貴族`、`小貴族`、`獸人` 沒有人物資料，天然不會被辨識。
- **00 頁人名也可點**（Popover），只是不標亮追蹤。
- 已在 `{…}` 標記內的片段不再重複辨識（避免巢狀重複）。
- 錯別字別名（`艾利絲`、`艾莉`、`利歐欄`、`盤神`）寫進 `aliases` 並加註記 `typo:true`，**僅供搜尋比對用，渲染時顯示原文不修正**；建議作者直接修正原文。

## 3. 伏筆回收處（`{h:…}`）撰寫規則

1. 片語取**敘述中自然的連續文字**（可跨行、可包含人名連結），長度建議 4–15 字；雙底線會畫在整個片語下。
2. `hint-id` 必須存在於 `hints.yaml`，且該伏筆的 `recycle.axis/event` 必須就是這個標記所在的頁與事件。
3. 同一事件內多個片語**不可重疊**；同一行可有多個（框格會自動錯開）。
4. **不需要**標註行號、座標或「框格要放哪」。桌機框格 y 由片語所在行自動算出；流式版框格自動插在片語後第一個標點之後。
5. 片語後面最好有標點（，；。）；若沒有，流式版註記列會插在片語正後方。
6. 事件敘述長度與框格數：每個事件建議 ≤ 3 個回收處（03 事件 06 有 3 個，已是上限範例）。

範例（03 事件 06，節錄）：
```yaml
- n: 6
  title: 地底大洞
  tag: 地底
  participants: [nor, elian, fane, lioran, bren, rumi]
  text: >-
    教會坍塌後，{p:nor}和{p:rumi}趕到大洞邊。…
    {p:elian}{h:useful-to-witch|受{p:nor}之託和{p:fane}深入地底}，找到{p:bren}；
    {p:fane}告訴{p:bren}{t:snake-god}不是人類。
    {h:forgotten-gift|{p:fane}用馬蹄鐵敲出火}、燒鬃毛蓋過{h:spirit-scent|盤蛇的氣味}，並棒喝{p:elian}：界線不可能消失。
```

## 5. 劇透標記（人物誌完整介紹）

在 YAML 中以結構表達（`bio: [{type: text}, {type: spoiler, axis: 3}]`），**不**沿用 `[劇透:03]…[/劇透]` 純文字標記（避免解析歧義）。提供一支轉換腳本 `scripts/convert-bio.ts`，把 `內容準備與設計稿修改.md` 中既有的 `[劇透:主軸]…[/劇透]` 一次轉成結構（任務 T034），之後以 YAML 為準。

## 6. 為什麼這樣設計（回答「文字排版因螢幕不同，如何找位置」）
- 程式**不知道、也不需要知道**文字會在哪一行：它在畫面上對 `data-hint` 的 span 量測 `getClientRects()`。
- 作者只需保證「片語存在、id 對得上」，建置驗證會替你把關。
- 修改文字（增刪、換字型、compact 字級）→ 框格與弧線**自動重新量測**（見 research R8）。
